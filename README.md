# 7주차 실습과제 — 파이프와 FIFO

시스템프로그래밍 7주차 실습과제입니다. 파이프로 부모-자식 프로세스가 통신하고, `dup2`로 두 명령을 셸처럼 이어 붙이고, FIFO로 서로 관계없는 두 프로세스가 메시지를 주고받습니다.

| 과제 | 파일 | 실행 예 | 원본 실습 코드 |
|---|---|---|---|
| 1. 파이프로 왕복 | `1_pipe.c` | `./1_pipe "hello world"` | `1_pipe_basic.c` |
| 2. dup2로 명령 이어 붙이기 | `2_pipeline.c` | `./2_pipeline ls -l : wc -l` | `2_pipe_dup2.c` |
| 3. FIFO로 메시지 주고받기 | `3_fifo_recv.c`, `4_fifo_send.c` | `./3_fifo_recv` → `./4_fifo_send 안녕` | `3_fifo_read.c`, `4_fifo_write.c` |
| 도전 과제: 여러 클라이언트 FIFO 서버 | `3_fifo_recv.c` (`-l` 옵션) | `./3_fifo_recv -l` | — |

## 1. 파이프 두 개로 왕복 — `1_pipe.c`

부모가 보낸 문자열을 자식이 대문자로 바꿔 돌려줍니다. 파이프는 단방향이라서 왕복하려면 두 개가 필요합니다.

```
부모 ──p2c[1] 쓰기──▶ [p2c] ──p2c[0] 읽기──▶ 자식
부모 ◀──c2p[0] 읽기── [c2p] ◀──c2p[1] 쓰기── 자식
```

파이프가 두 개면 fd가 네 개이고, 각 프로세스는 쓰지 않는 두 개를 닫습니다.

|        | `p2c[0]` 읽기 | `p2c[1]` 쓰기 | `c2p[0]` 읽기 | `c2p[1]` 쓰기 |
|--------|:---:|:---:|:---:|:---:|
| 부모 | **close** | 사용 | 사용 | **close** |
| 자식 | 사용 | **close** | **close** | 사용 |

**흐름**
1. 부모가 `p2c[1]`에 문자열을 쓰고 **바로 `p2c[1]`을 닫습니다.**
2. 자식은 `read(p2c[0])`가 0(EOF)을 돌려줄 때까지 읽고, 읽은 만큼 `toupper`로 바꿔 `c2p[1]`에 씁니다.
3. 자식이 `c2p[1]`을 닫고 종료하면, 부모의 `read(c2p[0])`가 EOF를 보고 결과를 출력합니다.
4. 부모가 `waitpid`로 자식을 거둡니다(좀비 방지).

- 한 번의 `read`/`write`로 다 오간다는 보장이 없으므로 `write_all()` 반복 쓰기와 EOF까지 읽는 루프를 썼습니다.
- `toupper`에 `unsigned char`로 넘기므로 한글 같은 UTF-8 다바이트 문자는 바뀌지 않고 그대로 돌아옵니다.

## 2. dup2로 명령 이어 붙이기 — `2_pipeline.c`

```bash
./2_pipeline ls -l : wc -l      # == ls -l | wc -l
```

- `argv`에서 `:`를 찾고, 그 자리를 `NULL`로 바꿔 인자 배열 두 개(`cmd1`, `cmd2`)로 나눕니다. 이렇게 하면 따로 복사하지 않고 `execvp`에 바로 넘길 수 있습니다.
- **자식 A**: `dup2(fd[1], STDOUT_FILENO)` → 원본 fd 닫기 → `execvp(cmd1)`. 앞 명령이 표준출력에 쓴 내용이 파이프로 들어갑니다.
- **자식 B**: `dup2(fd[0], STDIN_FILENO)` → 원본 fd 닫기 → `execvp(cmd2)`. 뒤 명령이 표준입력으로 파이프를 읽습니다.
- **부모**: `fd[0]`, `fd[1]`을 **둘 다 닫습니다.** 부모가 쓰기 끝을 들고 있으면 `wc`가 EOF를 받지 못해 끝나지 않습니다.
- 두 자식을 모두 `wait`하고, 셸처럼 **마지막 명령의 종료 코드**를 프로그램의 종료 코드로 돌려줍니다.
- `:`가 없거나 앞·뒤 명령이 비어 있으면 사용법을 출력하고 1로 종료합니다. exec가 실패하면 127로 종료합니다(셸 관례).

셸의 결과와 같은지 나란히 비교했습니다.

## 3. FIFO로 메시지 주고받기 — `3_fifo_recv.c` / `4_fifo_send.c`

**받는 쪽을 먼저 실행합니다.** 받는 쪽이 `mkfifo("/tmp/sysprog_fifo")`로 FIFO를 만들고 `open(O_RDONLY)`에서 기다립니다. 보내는 쪽이 `open(O_WRONLY)`하는 순간 양쪽이 함께 진행됩니다. 두 프로그램은 부모-자식 관계가 아니고, FIFO의 **이름**만 공유합니다.

```bash
# 터미널 A
./3_fifo_recv
# 터미널 B
./4_fifo_send "안녕하세요" "두 번째 메시지"     # 인자 하나 = 메시지 한 줄
printf '줄1\n줄2\n' | ./4_fifo_send              # 인자가 없으면 표준입력에서 한 줄씩
```

- **메시지 규약**: 파이프는 경계가 없는 바이트 스트림이라서 `"hello"`와 `"world"`를 따로 써도 붙어서 읽힐 수 있습니다. 그래서 **메시지 하나 = 줄(`\n`) 하나**로 정했고, 받는 쪽은 버퍼에 모은 뒤 `\n` 단위로 잘라 출력합니다.
- **원자성**: 보내는 쪽은 메시지 한 줄을 `\n`까지 붙여 **한 번의 `write`** 로 보내고, 길이는 `PIPE_BUF`(4096) 이하로 제한합니다. 그래서 여러 클라이언트가 동시에 써도 줄이 섞이지 않습니다.
- 보내는 쪽은 `stat` + `S_ISFIFO`로 FIFO가 실제로 있는지 먼저 확인합니다. 받는 쪽을 먼저 실행하지 않았으면 안내 메시지를 출력합니다.
- 보내는 쪽은 `SIGPIPE`를 무시합니다. 받는 쪽이 중간에 사라지면 조용히 죽지 않고 `EPIPE`로 알아차려 메시지를 출력합니다.
- 끝나면 받는 쪽이 **`unlink`로 FIFO를 지웁니다.** 실행 후 `ls /tmp/sysprog_fifo`로 남은 파일이 없는지 확인했습니다.

## 본인의 보강 내용

기본 요구사항 외에 직접 확인하고 덧붙인 부분입니다.

1. **부분 읽기/쓰기 처리**: `read`/`write`가 요청한 바이트보다 적게 처리할 수 있다는 점을 반영했습니다. `write_all()` 반복 쓰기와 EOF까지 읽는 루프를 넣고, 부모 쪽 결과 버퍼는 `realloc`으로 늘려 긴 문자열도 처리합니다.
2. **close 누락 교착 실험**: `-DBUG_NO_CLOSE` 빌드로 강의의 "멈추면 fd를 안 닫은 것"을 직접 재현했습니다. 교착이 양쪽 프로세스에 걸쳐 일어나는 이유도 정리했습니다(자식은 p2c EOF 대기, 부모는 c2p EOF 대기).
3. **임의 명령 파이프라인**: `ls -l | wc -l`만 되는 고정 코드가 아니라 `execvp`와 `:` 구분자로 임의의 두 명령을 잇습니다. 종료 코드도 셸처럼 마지막 명령의 것을 전달합니다.
4. **FIFO 메시지 경계 규약**: 줄 단위 메시지와 `PIPE_BUF` 이하 단일 `write`로 "파이프에는 경계가 없다"는 한계를 응용 수준에서 해결했습니다.
5. **도전 과제**: EOF 뒤 재`open` 방식의 여러 클라이언트 서버를 만들고, `quit`·Ctrl+C 어느 쪽으로 끝내도 FIFO를 `unlink`하도록 했습니다.
6. **SIGPIPE/EPIPE 처리**: 보내는 쪽은 `SIGPIPE`를 무시하고 `EPIPE`를 검사해서, 받는 쪽이 사라졌을 때 이유를 알리고 종료합니다.
